# 三套方案对比

对比对象：`prototype-a.html`（凭据）、`prototype-b.html`（窗格）、`prototype-c.html`（手卡）。
三者使用同一份示例数据，覆盖同一组状态：空态、命中、追问、歧义、未命中、转专业计划。

## 评分表

| 维度 | A 凭据（单栏文档） | B 窗格（对话 + 右栏） | C 手卡（移动优先） |
| --- | --- | --- | --- |
| 信息密度 | 高。答案、原文、清单、流程在一条竖线里连续排布，一屏能读完一件事；原文默认折叠，展开后不跳页。 | 最高。左栏只放"回答"，右栏常驻"条目档案"，原文、材料、流程同时可见；桌面 1440 下无一次跳转即可核对。 | 低。一屏一件事、一个动作，卡片 + 底部抽屉；信息要分层点开，适合手机，不适合横向比对。 |
| 学习成本 | 低。读起来像一张办事回执，从上往下即可；"NO.00X""骑缝线"是装饰性隐喻，不影响操作。 | 中。要理解"左问右查"的分工；但每个答案卡片都写着"在右栏核对全部"，一次点击即可建立心智模型。 | 最低。聊天 + 底部抽屉是手机用户的默认经验，几乎不需要解释。 |
| 动效 | 克制。一次性入场 240ms、原文折叠用 `grid-template-rows: 0fr→1fr`，没有位移动画。 | 克制且有用。右栏切换 tab 有 180ms 下划线滑动，移动端抽屉用 `--ease-drawer` 300ms 上滑，可拖拽关闭。 | 最丰富。卡片入场、抽屉拖拽（1:1 跟手 + 速度判定）、toast 2.5s 自动淡出；全部尊重 `prefers-reduced-motion`。 |
| 移动端 | 中。单栏天然适配，但"回执"的信息层级在 390px 下偏长，固定地图条容易压住内容。 | 好。≤900px 右栏降级为底部抽屉，答案留在主栏；桌面能力在手机上不丢失。 | 最好。为 390–430px 设计，44px 触控目标、安全区、单手可达的输入框。 |
| 实现成本 | 低。单栏 DOM，无面板状态同步；地图、抽屉都要另写。 | 中。需要维护"当前条目 + tab + 抽屉开合"三份状态，但接口数据本来就分"答案"与"条目"两块，正好对应两栏。 | 中高。手势、抽屉、滚动锁定、键盘避让都要单独处理，桌面端还要做居中壳。 |
| 适合的场景 | 打印/存档、答辩时逐条念给人听。 | 桌面演示、真实使用的主场景；一屏内完成"问—核—带走"。 | 手机端日常使用、路演扫码即用。 |

## 推荐：B 窗格

理由按重要性排序：

1. **证据和结论在同一屏，且互不挤占。** 产品的底线是"每句结论都能核到原文"。A 把原文折在结论下面，展开会把后面的内容推走；C 要打开抽屉才看得到原文，核对成本最高；B 的左栏回答与右栏原文并列，点"核对原文"只是切换右栏 tab，视线不离开当前问题。
2. **接口结构就是两栏结构。** `/api/ask` 返回的 `answers/quotes` 是"这次问了什么"，`item/materials/steps/pitfalls/source` 是"这件事的档案"。A/C 都要把两份数据压进一条时间线，B 让它们各归其位，后续加"拍照核对""地图"也不用重排。
3. **地图面板有地方放。** 任务要求预留 `<aside id="map-panel">`。B 的右栏本身就是"空间"的容器，地图可作为可拖拽浮层停在右栏下缘，不遮挡输入；A 的固定浮层会压住回执，C 则要占一个 tab。
4. **移动端有明确降级路径。** 右栏在 ≤900px 变成底部抽屉，答案主栏不变。这比 A"整页变长"、C"桌面另做一套壳"更省实现成本，也保证手机上仍能核对原文。
5. **演示叙事更强。** 桌面投影时，观众能同时看到"问句 → 结论 → 原文 → 材料清单"，评委不必等你点开折叠区。

## 从 A、C 借用的部分

- 来自 A：原文引文的衬线排版与"原文 n 条"入口；回执式的元信息网格（部门/渠道/费用/用时/地点）；"官方没写就不编"的缺失提示。
- 来自 C：移动端底部抽屉的拖拽关闭与速度判定；输入框上方的一键问法；toast 的 2.5s 自动淡出。
- 来自 B 自身并保留：主栏"复制答案 / 核对原文 / 清单与流程"三键，是"带走"这件事的最短路径。

## 不推荐直接采用 A / C 的原因

- A：单栏在 1440 下每屏只承载一个状态，追问一多就要滚动；地图浮层与回执争夺右下角。
- C：桌面端只是"手机壳居中"，浪费横向空间；核原文需要额外一次手势，和"证据优先"的定位相反。

## 落地说明

`web-next/` 按 B 实现，并吸收上述 A/C 的细节；未采用框架与构建步骤，纯静态三件套，直接用 FastAPI `StaticFiles` 托管即可。
