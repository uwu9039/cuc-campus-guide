# 校园办事向导三版前端视觉稿设计

日期：2026-11-01

## 1. 目标

为现有校园办事向导制作三版可直接打开、可比较、可在手机与桌面浏览的纯 HTML 视觉稿。三版使用同一份“校园卡丢了怎么办”示例内容，让用户只比较视觉与信息组织，不受问答内容差异影响。

本轮只用于选型。现有默认前端 `/`、旧版 `/classic`、后端接口、事项数据和启动方式均不改变。

## 2. 已确认的方案

### 2.1 清透校园

定位为正式版的优先候选。使用暖白背景、深墨绿主色和少量砖红强调，配合圆角卡片、清楚的双栏层级和较大的提问入口。整体轻快、现代、可信，避免装饰压过办事信息。

首屏以“今天要办什么事？”为主标题。答案状态左侧呈现结论与办理步骤，右侧呈现材料清单和官方依据。空状态与答案状态可以切换。

### 2.2 纸张档案

保留现有产品的纸张与证据气质，但改为更明确的编辑式网格。使用米白、黑红、衬线标题、条目编号、细分隔线和印章式状态标记。信息密度高于清透校园版，接近一本可打印的校园办事手册。

页面强调“问题—结论—证据”的阅读顺序。材料与步骤采用清单排版，原文采用引文排版，少用悬浮式卡片。

### 2.3 深色智能中枢

使用炭黑与深绿背景、荧光绿状态色和高对比文字。提问入口与证据面板具有明确的数据工具感，适合比赛演示与大屏展示。

深色只用于视觉表达，不牺牲长文阅读。正文、材料和原文保持足够字号与行距，状态色不承担唯一的信息表达。

## 3. 三版共同内容

三版使用相同的示例问题与信息架构：

- 示例问题：“校园卡丢了怎么办”。
- 答案区域：核验状态、系统理解、核心结论、办理地点或时间、办理步骤。
- 材料区域：可勾选的材料清单与完成进度。
- 依据区域：官方原文摘录、来源名称与“以官方原文为准”提示。
- 辅助入口：联系方式、搜原文、打印或复制清单的界面表现。
- 示例问题入口：校园卡、成绩单、转专业等常见问法。

视觉稿中的示例内容只用于展示设计，不新增或修改任何校园事实，不作为正式问答数据。

## 4. 文件与实现边界

视觉稿放在独立目录 `design/frontend-visual-directions-2026-11-01/`：

- `clear-campus.html`：清透校园版。
- `paper-archive.html`：纸张档案版。
- `dark-command.html`：深色智能中枢版。

每个文件内含自己的 CSS 与少量原生 JavaScript，不依赖框架、构建工具、网络字体、CDN 或后端服务。三页可以互相跳转，便于比较。

不修改 `web-next/index.html`、`web-next/styles.css`、`web-next/app.js`、`web-next/classic.html` 和 `app.py`。本轮不将任何视觉稿接入正式路由。

## 5. 交互与状态

每版至少提供以下可在本地操作的交互：

- “空状态 / 答案状态”切换，用于比较首屏与办事结果。
- 点击示例问题后填入提问框；视觉稿中的演示提交只切换到同一示例答案，不伪装成真实后端请求。
- 材料项可勾选，并同步更新完成数量或进度。
- 原文依据可展开或切换查看。
- 移动端将右侧档案改为文档流或底部面板，不出现横向溢出。

交互只改变当前页面内的演示状态，不写入 localStorage，不读取个人信息，不发起网络请求。

## 6. 响应式与可访问性

桌面按 1440×900 检查，窄屏按约 390×844 检查。三版均使用语义化标题、按钮、列表与表单标签；键盘可聚焦所有交互元素；焦点样式清楚；正文与背景保持足够对比度。

动画只用于轻微的状态过渡，并支持 `prefers-reduced-motion`。不使用持续循环背景动效，不让动画妨碍阅读与点击。

## 7. 旧版备份与回退

制作视觉稿前，将当前 `web-next` 整个目录原样复制到 `_backups/web-next-before-visual-directions-2026-11-01/`。备份只保存在本机，不上传。

本轮因为不改现有前端，回退边界天然成立：默认 `/` 与 `/classic` 始终保留。后续若用户选定一版接入正式前端，必须在接入前再次确认备份完整，并保留可直接访问的旧版入口；恢复时用备份目录覆盖对应前端文件即可。

项目根目录没有 Git 元数据，因此备份与回退不能依赖 Git。

## 8. 验证与验收

完成后逐项检查：

1. 三个 HTML 文件均能直接打开，无 404、外部资源依赖或控制台脚本错误。
2. 三版的空状态、答案状态、示例问题、材料勾选和原文查看均可用。
3. 桌面与窄屏下无横向溢出，主要文字、按钮和材料清单可读可点。
4. 三页之间可互相跳转，浏览器返回操作正常。
5. 现有 `/` 和 `/classic` 保持原样，后端与数据文件未改动。
6. 备份目录包含当前 `web-next` 的完整副本。
7. 最终向用户提供三个本地文件链接，并展示实际渲染效果；说明已检查项目与未能检查的项目。

验收目标是帮助用户选定视觉方向，不是在本轮完成正式前端替换。
