# 体测计算器（/tice.html）设计

日期：2026-11-07
状态：待复看
参照物：微信小程序「白杨口袋」体测功能（appid `wxf73dc2f086e42ea0`，v2 包），属师哥传承项目

## 1. 一句话

把白杨口袋的体测功能原样搬到广院通里，做成一个独立页面，功能项一条不加一条不减，UI 按我们的钴蓝场重画，评分表用传承包里那份（已核对），页面打「仅供参考」小字。

## 3. 范围：与他逐条对齐

| # | 功能 | 验收口径 |
|---|---|---|
| 1 | 计算页：性别 + 年级 + 七项输入 | 出单项得分、加权贡献、标准分、附加分、总分（120 制）、等级 |
| 2 | 四态标签 | `已计算 / 待填写 / 需修正 / 规则待确认`，四项文案与触发条件照他 |
| 3 | 输入体检 | 单位混淆逐个检测：肺活量升↔毫升、跳远米↔厘米、坐位体前屈毫米、体重克与斤、50米漏小数点、正负号冲突、长跑必须整数分:秒且秒在 0–59；汇总句「检测到 N 项疑似异常输入，当前仍按填写值计算成绩，不影响评分结果」 |

不做：训练建议、目标反算、AI 咨询（他包里没有）；不接问答路由；不改 `/api/ask` 与 SSE 契约；不做服务端账号；不搬他的代码，只搬标准数据。

他包里还有一个 `adsEnabled / adInsertAfter` 的「预留信息流广告位（当前未启用）」开关，不复制——我们本来不放广告，留个空开关只会让人以为能开。

## 4. 接法：方案二（不碰 app.py）

`app.py` 一行不改。前端文件直接放 `web-next/`，由现有的 `app.mount("/", StaticFiles(directory=web-next, html=True))`（[app.py:6692](app.py#L6692)）伺服。

**地址只能写 `/tice.html`。** Starlette 的 `html=True` 只做两件事：目录请求补 `index.html`、找不到时试 `404.html`，不给无后缀路径补 `.html`（[.venv/.../staticfiles.py:140-155](.venv/Lib/site-packages/starlette/staticfiles.py#L140)）。所以 `/tice` 必然 404。

好处：零后端改动，不撞正在跑的后端进程，不碰发布包里的 app.py。代价：地址不好看，`/field` 与经典版的入口链接都得写全名。

## 6. 数据层

从传承包 `data/fitness-standard.js`（19,268 字符）转录，结构：

```
meta            标准名/文号/校内办法名/文号/施行范围/verifiedDate/来源与核对说明
scoreLadder     20 档：100 95 90 85 80 78 76 74 72 70 68 66 64 62 60 50 40 30 20 10
                对应等级：100-90 优秀 / 85-80 良好 / 78-60 及格 / 50-10 不及格
weights         BMI .15 肺活量 .15 50米 .20 坐位体前屈 .10 立定跳远 .10 力量 .10 长跑 .20
limits          maxStandardScore 100 / maxSingleBonusScore 10 / maxTotalBonusScore 20 / maxTotalScore 120
grades          大一 大二 大三 大四 → grade12 / grade34 两组
bmiCategories   男女各 4 类：正常100 低体重80 超重80 肥胖60，含 scaled 整数边界（×10）
rawThresholds   24 张表 × 20 槽位 = 480 槽，实测 470 个数 + 10 个 null：
                肺活量 / 50米 / 坐位体前屈 / 立定跳远 四项男女都有（4×2×2 = 16 张，满档）
                1000米只存 male、800米只存 female（2×2 = 4 张，满档，值为分秒字面量）
                仰卧起坐只存 female（1×2 = 2 张，满档）
                引体向上只存 male（1×2 = 2 张），两个年级组各在第 5/7/9/11/13 槽为 null，
                对应 78/74/70/66/62 分——原表就没有独立次数阈值，他包里的
                unpopulatedScores 字段就是记这件事的，不是转录遗漏。
                整数类（肺活量、立定跳远、次数）直接给整数
                一位小数类（50米、坐位体前屈）给字符串 "7.5" / "-1.3"
                跑类给分秒字面量 "3'17\""，解析成秒比较
bonusTiers      4 张：力量类两档制（多做次数）、长跑类两档制（少跑秒数）
unresolvedRules 3 条，见 §8
```

**比较一律走整数刻度**（一位小数 ×10、时间换算成秒），不用浮点。他包里有 `pow10BigInt` 和 `scaled*` 字段，就是在规避这个坑，我们照做。

BMI 只出分类得分（正常100/低体重80/超重80/肥胖60），**不插值**，与他一致。

## 7. 附加分

`bonusEligible` 为真的只有力量项与长跑项。机制照他：每张事件表挂一个 `bonusTable`，按 `direction` 从高往低扫，命中档位取 `bonusScore`，单项封顶 10；`strengthBonus + enduranceBonus = totalBonus`，总封顶 20；总分 = 标准分 + totalBonus，上限 120。

两张力量表的 `delta` 不同（一张 1–10，一张 2–13），两张长跑表的 `reductionSeconds` 不同（一张 4–35，一张 5–50）。**具体哪张挂给哪个事件、男女各按哪张，实现时直接从包里读 `FITNESS_STANDARDS` 的挂法照搬，不自己推。** 这条列为实现第一步，不留在设计阶段猜。

## 8. 三种「算不出来」

他显式建模了 `UNRESOLVED_POLICY_RULES`，我们原样保留，状态叫 `规则待确认`：

1. `bmi_boundary_precision_unresolved`：国标 BMI 表只列一位小数区间，相邻区间留 0.1 空隙（17.85、23.95、27.95），落入空隙无法定分类。
2. `measurement_precision_rounding_unresolved`：输入精度高于评分表刻度（如 50 米填 6.75 秒）且向下取位与向上取位跨档时，因未核实学校设备的统一取位规则，不擅自四舍五入或截断。
3. `cuc_2024_policy_multi_year_scope_unresolved`：校内办法（本科生院〔2024〕115号）注明自 2024 级本科生起施行，2023 级及更早的适用性不作推断。

这三条的价值在于：拿不到唯一分时说拿不到，而不是凑一个数。和我们问答层「原文没写的字段显示官方没有写」是同一条原则。

## 9. 存储

```
localStorage key  tice_draft_v1     当前填写 + 时间戳，输入去抖后写入
                  tice_archives_v1  按学年的存档数组
```

存档记录字段：学年、性别、年级、七项原始输入、七项结果、标准分、附加分（力量/长跑分列）、总分、等级、状态、保存时间，加 §9.1 的可选档案资料。

四条保护，全部照他的行为：

1. 读取失败或结构版本不认识 → 保留原数据不覆盖，提示「本地暂存读取失败或版本暂不支持，原数据已保留；当前填写暂不能覆盖它」。
2. 写入失败 → 明示「自动暂存失败，当前填写仍在页面中；请勿将本机记录作为唯一凭证」，不假装成功。
3. 删除失败 → 「删除失败，原记录已保留」。
4. 存档被替换失败 → 「保存失败，原存档未被替换，请稍后重试」。

localStorage 在隐私模式下可能整体不可用：整页要能在无存储下正常算分，只是暂存与历史降级为不可用并说明原因。

### 9.1 档案编辑浮层（从他编译模板里读出来的原样）

浮层标题随状态切换：新建时「保存本次记录」，改旧档时「编辑档案信息」。字段六个：

| 字段 | 必填 | 说明 |
|---|---|---|
| 姓名 | 否 | 只落本机 |
| 学院 | 否 | 只落本机 |
| 专业 | 否 | 只落本机 |
| 入学年级 | 否 | 他的占位写作「如2025级」 |
| 学年 | **是** | 存档的键，缺失时提示「请填写学年」 |
| 备注 | 否 | 只落本机 |

两个开关与三个按钮：

- `preserveSavedProfile` 反向的一次性模式，他的原文「一次性资料 · 仅保存本条记录，不更新常用资料」——勾了就只写这条存档，不动常用资料。
- 隐私标注原文「仅保存在本机 · 不主动上传服务器」。
- 「清空本次资料」清六个字段，不动算分结果与成绩。
- 「取消」丢弃本次改动，「保存」落盘并沿用 §9 的失败保护。

一条要守的纪律：姓名/学院/专业是可选项且永不离开设备。任何导出、复制、分享路径都不带这三个字段，测试里加一条断言防回归——这条和我们发布前抹身份的既有口径是同一条。

## 10. 文案

总分卡下方小字（这次新增的要求）：

> 仅供参考，实际成绩以学校体测系统记录为准。

页尾声明块三段：本表来源与核验说明（国标文号 + 校内办法文号 + verifiedDate + 由传承核对人本人逐项核对）、仅本机存储不上传、换设备或清数据可能丢失且勿作唯一凭证。

四态、三种未完成、各条单位混淆提示，逐条照他的字符串搬，不改写、不加「温馨提示」腔。引用校方规定时保留原文限定词（「自2024级本科生起施行」「适用性不在本阶段单学年国家标准算分中强行推断」这类措辞原样留）。

## 11. UI 原则

改的是表现层，不改行为：输入校验、算分、状态判定、存储保护全部照他。

页面结构四块：计算区（性别/年级两个分段选择 + 七项输入 + 结果表）、总分卡（标准分 / 附加分 / 总分 / 等级 / 小字）、历史区（存档列表 + 状态标签 + 编辑/复制/删除）、声明区。档案编辑是第五块，以浮层形式出现，字段与开关按 §9.1。

窄屏优先（这是给学生手机上看的），键盘可达、错误提示与输入框关联、状态用文字不只用颜色。

空态：本机一条存档都没有时，历史区不画空列表，直接给一句「还没有本机存档，算完一次可保存」＋保存入口；存储整体不可用时换成「本机存储不可用」并说明原因，两种空态文案不得混用。

## 12. 测试

`tools/test_tice.py`（沿用 `tools/test_field_ui.py` 的静态契约风格）：

1. 结构不变量：每张表必须正好 20 个槽位；非 null 阈值按分值降序单调（`higher_is_better` 不增、`lower_is_better` 不减）；权重和 = 1.0；BMI 四类区间拼起来对 scaled 刻度不留缝、不重叠；`limits` 四项等于 100/10/20/120。
2. 空缺档位：全表 null 必须**正好**出现在引体向上两个年级组的第 5/7/9/11/13 槽，共 10 个；其他任何位置出现 null 都算转录出错，其他表出现 null 直接红。总数锁 24 张 / 480 槽 / 470 数。
3. 性别归属：男生取引体向上与 1000 米、女生取仰卧起坐与 800 米，按错性别去查必须报错，不许静默回退到另一套表。
4. 假阳性探针：故意注入一处乱序与一处档位缺失，两项必须都变红，证明检查不是空过。
5. 文件契约：`tice.css` 无裸色值、`tice-standard.json` 是唯一数据源（其余文件不得内嵌阈值）。
6. 隐私契约：存档的姓名/学院/专业三个字段不得出现在任何复制或导出文本里，注一份带姓名的存档跑一遍导出，断言输出中查不到该姓名。

`tools/test_tice_calc.js`（Node 跑，无需 npm）：边界用例不少于 20 条——正好等于某档阈值、落在两档空隙、BMI 四类边界与 0.1 空隙、`-0.0` 与坐位体前屈负值、`4:60` 非法秒、`3:7` 一位秒、总附加分超 20 被截、七项只填五项不生成总分、年级映射到组别、精度跨档返回 unresolved。

数据转录校验：已由本人于 2026-11-07 对照传承文件逐项核过，不再另开独立 PDF 抽查工序。测试仍做结构不变量，因为它查的是转录自洽，不依赖外部资料。
