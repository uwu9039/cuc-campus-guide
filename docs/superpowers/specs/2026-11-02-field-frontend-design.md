# /field 钴蓝场前端设计

日期：2026-11-02
状态：第一期已交付并按用户反馈修订；第二期三块已实现（见第 7 节）
选型来源：2026-11-01 视觉方向选型，第 31 版「钴蓝场」`cobalt-blue.html`（`#2B5BFF` + 白色强调字）

## 1. 目标与边界

给校园办事向导做一个新视觉的前端入口 `/field`，与现有 `/`（`web-next/index.html`）并行。第一期只做主链路：提问 → 答案 → 追问 → 交付。选型确认这版能用之后，再决定它是否取代 `/`。

改动清单是封闭的，只有四处：

- 新增 `web-next/field.html`
- 新增 `web-next/field.css`
- 新增 `web-next/field.js`
- `app.py` 在 `/classic` 路由之后、静态挂载之前，加一条 `GET /field`，照抄 `app.py` 里 `/classic` 那三行的写法（`FileResponse` + `media_type="text/html; charset=utf-8"` + `Cache-Control: no-store, must-revalidate`）

不动的东西：`index.html`、`app.js`、`styles.css`、`classic.html`、`personal-data.js`、`serve.py`、`vendor/`、`assets/`、`qr/`，以及 `items.json`、后端任何 API 与数据文件。`app.py` 除那条路由外不改。

（2026-11-02 修订追加：`index.html` 按用户反馈加了一条指向 `/field` 的入口，`assets/` 多出一个校徽文件，其余照旧。见第 7 节。）

三个新文件的后缀必须是 `.html` / `.css` / `.js`。`app.py:1410-1417` 的 no-cache 中间件按扩展名判断，改成别的后缀会绕过缓存控制。

打包不受影响：`tools/build_modelscope.py:83-86` 递归复制整个 `web-next/`，新文件自动进包。

动手前后各做一次备份与校验：

- 动手前把 `web-next/` 整目录复制到 `_backups/web-next-before-field-2026-11-02/`，`diff -qr` 要求为空
- 收尾时把三个新文件临时移出，再 `diff -qr web-next _backups/...` 要求为空，证明原文件一个字节没变

`README.md` 与 `start.bat` 第一期不改。`/field` 还是试验入口，写进启动提示等于替用户宣布选型结果。

`field.js` 与 `app.js` 之间会有约 40 行重复（请求封装、转义、字段取值）。这是有意的：不重构正在工作的 `app.js`，避免为了 DRY 把已验收的主链路重新推上风险。

## 2. 数据契约

只调用四个已有接口，不新增、不改参数：

- `GET /api/health`（返回 `items` / `verified` / `sources` / `data_updated` / `vector_chunks` / `key_configured`）
- `GET /api/campus?limit=500`（返回 `pois`，只用于把答案里的楼名连成地点）
- `POST /api/ask`，请求体沿用 `app.js:357` 的六个字段：`text` / `slots` / `router_llm` / `context_item` / `context_slots` / `messages`
- `POST /api/deliver`，请求体 `{item_id, slots}`

`/api/contacts` 属于第二期（联系方式抽屉），一期不调用。

返回渲染顺序沿用 `app.js:393-399` 的判定链，五种分支语义保持一致：

1. 有 `plan` → 渲染计划卡
2. `matched === false` → 未命中提示，不给编造答案
3. `disambiguate` / `clarify` → 澄清与候选选择
4. `hold` 为真或 `followups` 非空 → 挂起说明 + 追问按钮
5. 其余 → `answers[]` 主结果，每条含 `focus`、`label`、`text`、`steps[]`、`quotes[]`、`found`

硬性规则：

- `answers[].found === false` 显示「官方页面没有写这一项」，前端不得补造事实，不得用 `item` 里的其他字段兜底
- `quotes[]` 六个字段（`quote` / `src` / `label` / `kind` / `date` / `url`）原样呈现，引文不改写、不截断成另一句话
- 官方原文里的「原则上」「暂定」「建议」等限定词逐字保留，不得改写成「禁止」或「必须」
- `router_llm` 在无密钥时是显式 `false`，界面不假装调用过大模型
- 错误文案同时读 `error`、`detail`、`message` 三个字段。现有 `/` 只读 `detail`（`app.js:135`），后端 `app.py:4510` 抛的是 `{"error": ...}`，所以线上错误提示会丢失。`/field` 修这个缺陷，`app.js` 不动
- 深链只做 `/field?q=关键词`，进入时自动提问；不做前端路由

## 3. 视觉系统

Token 全部集中在一处，主题切换靠 `html` 上的 `data-theme` 属性，结构 CSS 里不出现任何裸色值：

```css
:root, :root[data-theme="cobalt-field"] {
  --bg: #ffffff; --ink: #111111; --accent: #2b5bff;
  --accent-ink: #ffffff; --muted: #5a5a5a; --line: #e3e3de;
  --radius-panel: 24px; --radius-pill: 999px;
}
```

钴蓝场基调：白底、近黑正文、`#2B5BFF` 做唯一强调色，强调色块上的字用白色。圆角只有面板 24px 与胶囊 999px 两档。不用阴影，不用玻璃拟态。

两种状态，随提问切换：

- **满屏场域**（进入时、清空后）：巨型大写标题 + 垂直轮换字幕 + 均衡条 + 金属球。字幕沿用选型稿的 `FIELD_WORDS` 池（10 词，`CUC` 出现 4 次并占首帧），每行 2.5 秒，末行复制首行做无缝循环。
- **双栏工作区**（出第一个答案后降级）：标题收进顶栏一行，金属球降到 `opacity: .12` 慢速漂移，均衡条冻结成栏间分隔线，左栏提问与追问，右栏答案与引证。

图形必须随滚动上下发生变化，不是静止背景——这是选型时定下的硬要求，降级后依然成立，只是幅度收小。

`prefers-reduced-motion: reduce` 时全部动画关闭，字幕停在 `CUC`。

四个第二期功能在一期就画出占位入口，标为未开放：地图抽屉、原文检索抽屉、联系方式抽屉、个人数据组件。灰态、不可点、旁边写「暂未开放」，点击不发任何请求，不留空跳转。二期把占位原地换成真入口，版式不再动。

## 4. 多主题预留

用户明确说了后期可能要换多种主题。为此一期就做到这三件事，别的都不做：

1. 颜色、圆角、字体档位只存在于 `:root` 的 token 块里，结构 CSS 一律用 `var(--x)`
2. 主题身份由 `html data-theme="cobalt-field"` 表达，不在 CSS 里写死第二套主题，也不提前做主题切换器 UI（2026-11-05 用户点名要夜间配色与顶栏开关，这一条已作废，见 §7 的「夜间配色与日夜开关」）
3. 场域动画的参数（金属球透明度、均衡条数量与高度档、字幕池与节奏）放在 `field.css` 顶部的变量注释块里，换主题时改数值不改规则

这样加一套新主题的实际成本 = 新增一个 `:root[data-theme="x"]` token 块 + 给 `html` 换属性值。若后期要运行时切换，再补一个读 `?theme=` 参数的分支即可，不需要重写版式。

一期不预先实现第二套主题，不做主题选择菜单——避免为还没发生的需求写代码。（同样是 2026-11-05 作废：第二套 `cobalt-dark` 与顶栏开关按用户点名落地，实际成本正好停在预言的那一步——多一个 token 块、换 `data-theme` 一个属性，版式与结构 CSS 一行没改。）

### 第二期三块 + 一块留禁用

第 3 节那四个「灰态不可点」的占位入口按原计划原地换成真入口，版式未动。三块都是右侧抽屉面板（`role="dialog" aria-modal`），共用一套开合、遮罩、Esc、焦点回位。

- **原文检索** `GET /api/search?q=&k=12`：只给官方原文段落与「打开原文」，明写「只给原文、不生成答案」；两个字以下不发请求，先提示；命中数与「最接近的 N 段」按后端字段如实说。
- **联系方式** `GET /api/contacts?purpose=`：15 类用途做成筛选条，电话 `tel:`、邮箱 `mailto:`，其余值只在有 `source_url` 时给链接；每条带「来源原文」，说明里点明「号码和邮箱会随部门调整，办事前核对那一条」。
- **地图** 复用已加载的 `/api/campus?limit=500`，不重复请求：接真底图，用仓库里已 vendored 的本地 Leaflet（`web-next/vendor/leaflet/`，非 CDN）+ 高德栅格瓦片，与经典版逐字同一条 `L.tileLayer("…webrd0{s}.is.autonavi.com/appmaptile?…")`、同一 `subdomains`、同一署名。189 个地点里官方给出坐标的 33 个用 `L.circleMarker` 画钴蓝点，坐标本身是 GCJ-02，与高德瓦片同基准，不做换算。面板明写「底图来自高德地图，图上只标官方给过坐标的地点：189 个里 33 个有坐标」，选中点披露 `coord_confidence`；官方没给坐标的地点（如「招生处」）不拿校园中心假造点，图上不标，详情如实写「官方没有给出这一处的坐标，图上不标点，只把范围放到校园这一片」，只给 `uri.amap.com` 深链。换面板时先 `view.remove()` 释放实例，否则再开地图撞 "Map container is already initialized"。

### 品牌块回首页（2026-11-02 追加）

顶栏的校徽 + 「广院通」由不可点的 `<span class="brand">` 换成 `<a class="brand" href="/field" title="回广院通首页">`。用户选的口径是**重新加载** `/field`，不是复用页内的 `resetToHero()`：链接不依赖 JS 就成立，重新加载会把问答痕迹、槽位与 `?q=` 深链参数一次清干净；代价是有白屏重载，与「返回」键属两套机制。`href` 写死干净的 `/field`（不是当前 URL），否则从深链进来点回去还会再问一次。CSS 只补 `text-decoration: none`，配色与版式不变；`field.js` 未改。

### 个人数据改成「只给官方入口」（2026-11-02 追加）

用户口径：顶栏「个人数据」点开只有校园卡、畅课两个链接，微信里提示「打不开请在浏览器打开」，查数据仍在官方系统里完成，向导页内不读取任何数据。这一条推翻了此前「留 `disabled` + 未接入」的决定，也推翻了第 3 节把它列为占位入口的安排。

实现边界按用户点名的两条收窄：地址**沿用经典版组件 `personal-data.js` 里的 `CARD_URL` / `COURSES_URL`**，`field.js` 顶部各留一份同名常量，测试逐字比对，两版不会点进不同系统；微信提示**只在微信里出现**，靠 `/MicroMessenger/i.test(navigator.userAgent)` 判定，普通浏览器不占版面。面板是 `PANELS.personal`（标题「个人数据 · 官方入口」），只有两个 `<a class="pdlink" target="_blank" rel="noreferrer">`，不嵌 `iframe`、不对 `pcard.` / `courses.` 发任何请求，说明文字明写「不读取」「由本人登录查询」。入口 `title` 也要含「不读取」，鼠标停上去先讲清页内不查数据。`.pdlink` 加进了面板首个焦点选择器，打开面板焦点直接落在第一个官方入口上。

随之清掉的：`#databtn` 的 `disabled` / `aria-disabled` / `<span class="soon">未接入</span>`，以及 CSS 里只服务于那个灰态的 `.ghostbtn[disabled]`、`.ghostbtn .soon`、`.plainbtn .soon` 三条死规则。浏览器门里原来那条「顶栏禁用入口应只剩 1 个」的断言改成「禁用入口应为 0 且不得出现占位说明」。

### 校医院落点更正（用户点名的数据修复）

用户实测指出：答案说校医院在 20 号楼是对的，但地图上的点标错了，要求「问校医院在哪的时候地图上面指向的是中国传媒大学20号楼，并且跳转到高德地图也是指向20号楼」。

根因在数据不在前端。`campus-map.json` 里校医院那条的坐标来自 OpenStreetMap 的 `amenity=hospital` 节点 N7321277718，换算成 GCJ-02 后用高德逆地理一核对，落在「中国传媒大学附属中学」一带，离 20 号楼约 451 米。前端只是老实画后端给的坐标，画得准、点错地方。

可复核的证据（没编坐标）：高德网页版 POI 接口 `www.amap.com/service/poiTips`（本机 urllib 可直连、不触发滑块验证，`poiInfo` 会触发）给出「中国传媒大学20号楼」= POI `B0FFF7RE6W` @ 116.558813, 39.913089；「中国传媒大学校医院」= POI `B000A9Q6CA` @ 116.558832, 39.913048，地址原文「定福庄东街1号中国传媒大学20号楼」，两点相距约 5 米——高德自己就把校医院登记在 20 号楼上。据此取 20 号楼那个点。

改了三处，都是用户点名的这一条数据链路：`tools/build_campus_map.py` 里 xiaoyiyuan 的 `src` 从 `(OSM, …)` 换成 `(AMAP, 39.913089, 116.558813)`，`source` 写上两个 POI 编号与核对过程，`note` 留被否决的旧点位和 451 米偏差的原因；`campus-map.json` 由脚本重新生成（37 个 POI、28 个有坐标，校园中心随之重算）；`app.py` 的 `MAP_QUERY` 把校医院的高德搜索词从「校医院」改成「20号楼」，`map_label` 不动，所以「在高德里打开」的搜索型链接也指到 20 号楼。这属于第 1 节「不动数据文件」的一次用户授权例外，例外范围只有这三处。

### 面板的两条几何与事件不变量

1. 面板与遮罩从顶栏下方开始，且这个高度是**实测**出来的：`field.js` 量顶栏 `getBoundingClientRect().bottom` 下发成 `--panel-top`，CSS 用 `var(--panel-top, var(--topbar-keep))`（`--topbar-keep: 84px` 只做 JS 没跑起来时的兜底），顶栏挂 `ResizeObserver` 跟着重算。写死的窄屏档位（曾为 `--topbar-keep-mobile: 172px`）已删——答完题顶栏会多出「当前事项 · …」一行，窄屏再换行，实测从 159px 长到 190px，任何常量都会压住入口。验收直接量真实几何：`面板顶 >= 顶栏底`，且 `document.elementFromPoint(入口中心)` 仍是那个入口。
2. 滚动锁定属性叫 `data-panel-open`，入口委托限定成 `button[data-panel], a[data-panel]`。两者曾因同名而互相吞事件：body 上的 `data-panel` 永远先被 `closest()` 命中，面板内部的选点与筛选全部走成「重新打开面板」。窄屏另有一条：满整行的规则写成 `.boxfoot .send`，不能是裸 `.send`，否则面板表单的按钮把输入框挤没。

### 等模型回话的中间态（2026-11-05 追加；2026-11-07 占位形态已换成思考框，见下一节）

用户口径：「输入但是还没出答案的时候先跳转回答将要开始的位置，然后做一个三点跳动的加载动画，等模型返回内容后再隐藏加载动画。」

实现只动 `ask()` 一处，顺序不能反：`addExchange(text)` 拿到这一问的槽位 `slot` → 把 `.thinking` 写进同一个槽 → `jumpToStart(slot)` → 才 `await api("/api/ask")`。先请求再点亮，等于答完了才动。隐藏不写单独的删除步骤：答案回来时 `slot.innerHTML = renderResult(response)`，失败时写 `errcard`，加载点随槽位一起被覆盖，所以错误分支也不会留下一个永远跳的三点。

三条不是可有可无的细节：

1. `.thinking` 要留 `min-height: calc(100vh - var(--panel-top, var(--topbar-keep)) - 90px)`。文档不够长时 `window.scrollTo` 会被滚动上限夹住，跳转根本落不到位——这条高度是「先跳到答案位置」能成立的前提，不是留白好看。
2. 跳转偏移读实测下发的 `--panel-top`，`--topbar-keep: 84px` 只当兜底。窄屏答完题顶栏会绕成两三行（实测 159→190px），只看常量会把刚点亮的三点顶到顶栏底下。
3. 顶栏是 sticky 且下滑会挂 `.is-up` 位移收起，所以跳转后量到的顶栏底边是负值；偏移仍按顶栏不收起时的高度留，用户往回滚一点顶栏滑回来时不会盖住三点。代价是三点上方有一段空白，桌面 90px、窄屏 127px。

一并撤掉的：答完后回到这一问开头的那次回跳（`if (fromOption) jumpToStart(...)`）与 `ask()` 的第三个参数 `fromOption`。既然点完选项要先跳到答案位置，答完再往回跳就把跳转抵消了；这条是顺着用户点名做的取舍，要保留回跳请说。经典版 `app.js` / `classic.html` 的加载提示未动。

### 反问卡关掉「为什么问」小字（2026-11-05 追加）

用户口径：「做完顺便把选项上面『为什么问』的小灰色字显示给我关了。」`holdCard()` 里每个追问的 `<p class="why">为什么问：…</p>` 整条不再渲染，问题行（`.aval` 的 `01 你住哪个公寓?`）与选项按钮照旧；`.why` 这条 CSS 规则随之删掉，不留没人用的规则。

这条推翻了第一期反馈 3 里「反问的理由要用轻量的 why 行呈现」的口径，测试按新口径反着钉：`holdCard()` 里不许出现 `class="why"` 与「为什么问」字样，同时仍要求 `class="aval"` 与 `class="opts"` 都在（防止连着把问题与选项一起删了），CSS 里不许再有 `.why {`。后端 `followups[].why` 仍在响应里，只是 /field 不显示；经典版仍显示，所以两版事实对齐门把这一条登记成「按用户口径主动不渲染」的说明，而不是 /field 缺失。

### 夜间配色与日夜开关（2026-11-05 追加）

用户口径两条：「顶栏加一个切换按钮」「按钮用那种开关键，复刻这个按钮」，并给了 51CTO 那篇「单标签下的日间/黑夜模式切换按钮效果」的原式 CSS。

### 思考框换掉三点跳动（2026-11-07 追加）

用户口径：「把三点跳动的加载动画换成思考过程，用符合风格的框套着，等模型返回内容后再隐藏掉。不要动后端，后端在改东西。」

先确认能拿到什么：`app.py` 没有 SSE / `StreamingResponse`，`/api/ask` 一次性返回，`llm()` 的 `thinking` 参数只管请求体、响应里也没有 `reasoning_content`——**模型的思考文本现在拿不到，进度也一条都没报**。把三条路摆出来（逐行点亮的阶段清单 / 只一句静态话 / 本轮只做框等后端透传真思考链），用户选**本轮只做框**。

于是框里什么都不写。`.thinking` 容器与它的 `min-height`、`padding-left: 1em` 一字不动（跳转落位的前提），里面换成 `.thinkbox`——配方照页面既有 `.genbox`：`--chip-bg` 底、`1px --line` 描边、左侧 `3px --accent` 竖条、半档圆角；框内只有一条 44% 宽的 `--accent` 细线走 `@keyframes field-think`（opacity .28↔.85，1.5s 循环）。三点那套整个退役，`.thinking i` 三条规则与 `@keyframes field-bounce` 一起删——留着 `.thinking i` 会串到框里的线上。收框机制没变：答案或错误卡覆盖同一个槽。

「不写阶段文字」是这一节的要点，不是偷懒：任何一行「正在检索…核对原文…」都是前端自己估的节奏，后端一个字都没报，写上去就是拿编的进度冒充思考过程。这条判断同时钉在 CSS 注释与测试里（`test_thinking_is_a_breathing_box_not_a_progress_script` 要求框内恰好一条 `<i></i>`、模板里没有文字节点），浏览器门 2.5 也加了「框内文字必须为空」这一断言。

后续（等后端这轮改完）：`llm()` 里读出 `reasoning_content`，随 `/api/ask` 回一个 `thinking` 数组，前端再把这些行逐条落进同一个框——那时才有真的思考过程可显示。
